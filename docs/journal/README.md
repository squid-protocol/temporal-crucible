# The experiment journal

A dated, plain-language lab notebook for the temporal-crucible program. **One entry per study, arc or finding.** Each
entry records:
- what we asked and why;
- what we did;
- what we found;
- the take-home;
- what it changed.

It sits beside the program's other records:

| record | what it is | when to read it |
|---|---|---|
| **This journal** | the narrative, in order, newest first | to follow what we learned and why |
| [`../TAKEHOMES.md`](../TAKEHOMES.md) | the take-homes, curated and grouped by theme | for the current state of knowledge |
| [`../HYPOTHESES.md`](../HYPOTHESES.md) | **the register of record**: every confirmatory claim, its registered direction and its verdict | for what exactly was claimed (it wins any disagreement) |
| [`../EXPERIMENTS.md`](../EXPERIMENTS.md) | the predictor × outcome map | for what has been tried against what |
| `../<study>_hypotheses.md`, `../<study>.md` | registrations and scored results | for how a study was done |

## Adding an experiment

1. **Open the entry when you register.**
   `python tools/journal.py new --date YYYY-MM-DD --slug <study> --title "..."` creates it from
   [`_template.md`](_template.md).
   - For a confirmatory study, set `status: registered`, `verdict: pending` and the register `ids`.
   - Commit the entry with the registration, before any outcome statistic.
2. **Score the study** under the usual protocol (scorer committed before the run; see `CONTRIBUTING.md`).
3. **Update the same entry.** Fill in "What we found", the take-home and "What it changed", then set `status: scored`
   and the `verdict`. Exploratory work uses `type: exploratory` and never carries a confirmatory verdict.
4. **Rebuild the generated sections:** `python tools/journal.py build`. This refreshes the index below and the list
   in `TAKEHOMES.md`. If the result shifts the big picture, also edit the curated part of `TAKEHOMES.md` by hand.
5. **CI runs `python tools/journal.py check`.** It fails on:
   - a missing or invalid field or section;
   - a register id that is not in `HYPOTHESES.md`;
   - a linked doc that does not exist;
   - a draft that carries a verdict;
   - a stale index.

Entries are never deleted. A study that is replaced gets `status: superseded` and a pointer to its successor.
Disclosure rule: entries are public, so they carry aggregates only (no per-host unpatched specifics).
